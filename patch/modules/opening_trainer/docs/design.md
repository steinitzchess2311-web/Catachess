# Opening Trainer 设计要点（Blue-White Minimal）

本文件用于补充 `functions.md` 的视觉与交互设计规范，目标是让 Opening Trainer 在风格上与 `catachess.com` landing 保持一致，同时支持复杂开局训练流程。

## 1. 可读性结论（现有文档）

`brainstorm.md` + `functions.md` 可理解且可执行，核心点清晰：
- 入口与准入条件明确（标准初始局面 + 至少 5 步变化）。
- 章节模式/合并模式边界明确（含 FEN 去重策略）。
- 分拆规则明确（对手多应法触发 + ply <= 8）。
- 三种训练模式和错题循环机制完整（Learn / Quiz / Preview + 连对 3 次）。

结论：可以直接进入 UI 与交互设计落地。

## 2. 视觉基线（对齐 Landing）

简略提取 `catachess.com` landing 当前样式特征：
- 主色：`#2563eb`
- 主色 hover：`#1d4ed8`
- 应用背景：`#f5f8fc`
- 卡片背景：`#ffffff`
- 主文字：`#0f172a`
- 次级文字：`#475569`
- 边框：`#e2e8f0`
- 字体：`"Inter", "Segoe UI", "Roboto", -apple-system, sans-serif`

整体方向：蓝白、简约、信息优先、轻动效。

## 3. 设计目标

1. 降低开局树复杂度，让用户始终知道“下一步去哪”。
2. 保持训练节奏连续，减少跳转焦虑。
3. 视觉强调“学习进展”，而非装饰性效果。

## 4. 页面信息架构

```text
Study 右侧栏
  -> Trainer 菜单
    -> Opening Trainer
      -> Opening Trainer 首页
        -> 卡片层级导航（章节或分拆单元）
          -> 最小训练节点
            -> 训练页面（Learn / Quiz / Preview）
```

## 5. 页面结构规范

## 5.1 顶部栏（固定）
- 左：返回 Study、面包屑路径。
- 中：当前层级标题（如 `1...e5` / `Sicilian`）。
- 右：模式切换（章节 / 合并）与视角标签（白 / 黑）。

## 5.2 主内容区
- 卡片网格（2-4 列，响应式降级）。
- 卡片显示：标题、包含线数、深度信息、视角标记、可训练状态。
- 不可训练卡片置灰并给出原因（例如未满足长度条件）。

## 5.3 训练区
- 棋盘为视觉中心。
- 右侧为“当前任务 + 提示 + 错题状态”面板。
- 底部为模式切换与主行动按钮（开始/继续/重试）。

## 6. 卡片与层级交互

## 6.1 卡片层级
- Chapter 卡片（章节模式）。
- 分拆单元卡片（如 `1...e5`）。
- 子分拆卡片（ply <= 8 内继续分叉）。
- 最小训练节点卡片（进入练习前最后一级）。

## 6.2 卡片状态
- `ready`：可进入。
- `locked`：条件不足（显示原因）。
- `in_review`：有错题待巩固。
- `mastered`：连对达标。

## 6.3 动效
- hover：轻微上浮 `translateY(-2px)` + 软阴影。
- click：快速回弹，避免重动效。

## 7. 训练交互要点

## 7.1 Learn
- 先演示，再回退，再跟练。
- 错误提示使用蓝灰提示条，不阻断流程。

## 7.2 Quiz
- 用户走自己视角，系统走对手视角。
- 对手多应法随机选线，并在回合标签显示“随机线路”。
- 走错后即时反馈：标红当前步并给出正确候选。

## 7.3 Preview
- 复用 position trainer 逻辑。
- 明确开关状态，避免用户误以为是 Quiz。

## 7.4 错题循环
- 错误步显示 `需连对 3 次` 进度条（如 `1/3`、`2/3`、`3/3`）。
- 训练完成后优先推送未掌握节点。

## 9. 文案与反馈规范

- 按钮文案使用动词：`开始训练`、`继续`、`重试`、`返回上层`。
- 错误文案简短直接：`该走法不在当前 repertoire 中`。
- 空状态文案给下一步动作：`当前没有可训练单元，返回 Study 添加变化线`。

## 10. 响应式要求

- 桌面端：棋盘 + 侧栏双列。
- 平板端：棋盘优先，侧栏下移。
- 手机端：卡片单列，训练区切换为上下结构。

## 11. 交付检查清单

1. 确认入口和准入条件提示完整。
2. 确认章节模式/合并模式路径都可达最小训练节点。
3. 确认 ply <= 8 的分拆在 UI 层级上可感知。
4. 确认 Quiz 随机对手应法有清晰反馈。
5. 确认错题连对 3 次机制有可视化进度。
6. 确认蓝白主题和 landing token 保持一致。
